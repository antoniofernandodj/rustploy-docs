**Schedules** (side menu) lists *run-once docker-compose tasks, scheduled or manual, from all projects*. The same jobs of a project
appear on its **Jobs** tab. What a job is and how it works is in [Jobs and scheduled tasks](/en/guias/jobs/).

## The list

<Shot
  src={schedules}
  alt="The Schedules screen with an empty jobs table and the first step of the New job window, which asks you to choose the project."
  caption="Schedules, with no jobs, and the New job window open on the project choice."
/>

At the top, the **JOBS** counter and the **+ Novo job** (New job) button. The table's columns:

| Column | Shows |
|---|---|
| **NOME** (Name) | the job's name |
| **PROJETO / GATILHO** (Project / trigger) | the project and the trigger service (or *standalone*) |
| **ÚLTIMA EXECUÇÃO** (Last run) | when it last ran |
| **RECORRÊNCIA** (Recurrence) | the schedule |
| **PRÓXIMA EXECUÇÃO** (Next run) | the next firing, **in your time zone** |
| **AQUECIMENTO** (Warming) | `quente` (warm), `frio` (cold) or `aquecendo…` (warming…) (see [Warm a job](/en/guias/jobs/#warm-a-job)) |
| **AÇÕES** (Actions) | the **⋯** panel with *Rodar agora* (run now), *Cancelar execução*, *Aquecer*, *Reconstruir (sem cache)*, *Ver logs*, *Editar* and *Remover* |

With no jobs: *"Nenhum job cadastrado ainda."* (No job registered yet.)

## Create a job

Click **+ Novo job**. The window has steps:

1. **ESCOLHA O PROJETO** (choose the project). *"O job sobe um stack docker-compose próprio; o projeto define a rede."* (The job starts a docker-compose stack of its own; the project defines the network.) Click **Selecionar ›**.
2. **Trigger service**, or **Nenhum (autônomo)** (None, standalone). The trigger only lends its environment variables.
3. **The form**, described below. The title shows *"NOVO JOB — project / service"* (or *"nenhum (autônomo)"*).

### Compose source: Compose

<Shot
  src={compose}
  alt="The New job form with the Compose source, an example YAML with the busybox image, the main service field and the environment variables field."
  caption="The New job form, with the Compose source."
/>

| Field | What it is |
|---|---|
| **NOME** | for example `backup-db` |
| **FONTE DO COMPOSE** | **Compose** (paste the YAML) or **Git** |
| **DOCKER-COMPOSE.YML** | the YAML. The screen brings a minimal example with `busybox` |
| **MAIN SERVICE** | the **name of the service inside the compose above** whose exit code decides whether the job succeeded |
| **VARIÁVEIS E SECRETS** (Variables and secrets) | when **editing**, the **🔑 Variáveis e secrets** button opens the panel (see [A job's variables and secrets](#a-jobs-variables-and-secrets)); when **creating**, the panel shows up in the next step, right after **Criar job**, because a job's secrets need its id. The job's variables win over the project's and the trigger service's |

### Compose source: Git

<Shot
  src={git}
  alt="The New job form with the Git source: account, repository and branch selectors, and the compose path in the repository."
  caption="The New job form, with the Git source."
/>

*"Selecione a conta conectada, o repositório e a branch. O repo precisa já ter um docker-compose.yml no caminho informado."* (Select the
connected account, the repository and the branch. The repo must already have a docker-compose.yml at the given path.) Choose the **CONTA GIT**
(Git account), the **REPOSITÓRIO** and the **BRANCH**, and check the **CAMINHO DO COMPOSE NO REPO** (compose path in the repo; default
`docker-compose.yml`). With no accounts, connect one in [Settings → Git](/en/interface/configuracoes/#git). The job **clones the repository on
every run**.

### Recurrence

<Shot
  src={recorrencia}
  alt="The end of the New job form with the recurrence Manual, Intervalo, Diária or Semanal and the Voltar and Criar job buttons."
  caption="The end of the form: the recurrence."
/>

| Option | Fields |
|---|---|
| **Manual** | none: it only runs when you tell it to |
| **Intervalo** (Interval) | every N hours |
| **Diária** (Daily) | a time |
| **Semanal** (Weekly) | a weekday and a time |

<Aside type="caution" title="The time is in UTC">
  The time you enter is **UTC**. The **PRÓXIMA EXECUÇÃO** column shows it in your time zone: use it to check.
</Aside>

Click **Criar job** (Create job). **‹ Voltar** goes back to the previous step.

## A job's ⋯ menu

<Shot
  src={jobsMenu}
  alt="A job's actions panel open over a project's job list, with the job name, the warm state and the Rodar agora, Aquecer, Ver logs, Pausar, Editar and Remover actions."
  caption="The panel from the ⋯ button (the job and project names are blurred)."
/>

The **⋯** button at the end of the row opens a panel with the job name, the warm-up state (*quente*,
"warm", and *aquecido em*, "warmed at", with date and time) and the actions:

| Action | Effect |
|---|---|
| **▶ Rodar agora** (Run now) | runs right away, outside the schedule. With a run in progress, it becomes **■ Cancelar execução** (Cancel run) |
| **◐ Aquecer** (Warm up) | pulls the images and builds the build cache **without running** the job |
| **↻ Reconstruir (sem cache)** (Rebuild, no cache) | shown with the job **warm**: rebuilds from scratch and pulls the images again. See [Rebuild from scratch](/en/guias/jobs/#rebuild-from-scratch) |
| **≡ Ver logs** (View logs) | the output (stdout and stderr) of the runs |
| **‖ Pausar** (Pause) | suspends the schedule. With the job paused, the button becomes **Ativar** (Enable) |
| **🔑 Variáveis e secrets** (Variables and secrets) | opens the screen with the job's environment variables and secrets. See [A job's variables and secrets](#a-jobs-variables-and-secrets) |
| **✎ Editar** (Edit) | opens the job to change it |
| **✕ Remover** (Remove) | deletes the job, after **asking for confirmation**. It cannot be recovered |

## A job's variables and secrets

The **🔑 Variáveis e secrets** action in the ⋯ menu opens a screen with the job's environment variables
and the **job's secrets**, with the same buttons as a service's *Environment* tab and the project's variables:

| Button | Effect |
|---|---|
| **✕** | removes the variable (or the secret) |
| **✏️** / **✎** | renames the key (the value stays) / edits the value in place |
| **🔒** | moves the variable to a **secret**: the value is stored encrypted (`ENC[age:…]`) |
| **🔓** | turns the secret back into a plain variable |
| **↑** | moves it up to the project: the project's services and jobs inherit it |
| **👁 / 🙈 / 📋** | shows, hides and copies a secret's value (the access is logged in the server audit) |
| **.env** | edits all variables as `KEY=VALUE` text |

At run time a job secret wins over the trigger service's secret, which wins over the project's.
**Every operation that changes or exposes a variable asks for confirmation**; only reordering doesn't.
This also applies to project and service variables.

## After creating

- If the job uses large images or a build, use **Aquecer** before the first run.
- To run the job **before every deploy**, add it to the service's pre-deploy queue: see
  [Domains, healthcheck and advanced options](/en/interface/servico-configuracao/#the-pre-deploy-queue).
