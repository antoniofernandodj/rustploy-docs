Rustploy keeps the infrastructure state (projects, services, jobs, Git accounts and settings) in
YAML files. **Download the infra** hands those files over as a `.zip`: a copy outside the server and
outside GitHub, good to keep and to check what is stored.

<Aside type="note" title="This replaced the old Infra as Code">
  There used to be an **Infra as Code** tab that exported and imported a manifest of its own
  (`rustploy.yml` + `rustploy.vars.toml`). It was a format parallel to the real state and was
  removed, along with the `ManifestApply`, `ManifestExport`, `ManifestExportAll` and `ManifestImport`
  commands. Agents or scripts that used them must move to the flow below.
</Aside>

## How to download

<Aside type="note">Available from daemon 0.1.34 (release v0.1.40).</Aside>

**Settings → Sincronização (Sync) → Baixar a infra (Download the infra) → Download infra**, in the desktop
app or the web UI. The file is `rustploy-infra.zip`. An agent uses the `InfraDownload` command.

## What is in the zip

The same tree [git sync](/en/guias/sincronizacao-git/) writes to the repository:

| File | Content |
|---|---|
| `MANIFEST.json` | format version |
| `settings.yml` | daemon settings |
| `providers.yml` | connected Git accounts (no plaintext token) |
| `projects/<id>/project.yml` | one project, with its services and jobs |

Secrets are written as `ENC[age:…]`: encrypted with the server key (and the recovery key, if set).
**Nothing leaves in plaintext.**

<Aside type="caution" title="The download refuses when there is a plaintext value">
  If the state has a value that should be encrypted (see **The gate** in
  [Git sync](/en/guias/sincronizacao-git/#the-gate-nothing-in-plaintext-enters-the-history)), the download is **refused**, with the same list as
  `InfraAudit`: it does not hand over what Git would not accept. Move the values to secrets and try again.
</Aside>

## Restoring

There is no "import the zip". Restoring means putting the tree in a repository and **syncing**: point
the new server at the repository and use the same recovery key. The steps are in
[Restoring on a new server](/en/guias/sincronizacao-git/#restoring-on-a-new-server).

## To copy just one service

Use the [service bundle](/en/guias/copiar-servico/) (**Exportar serviço** and **Importar**). The
`service` fields are in the [format reference](/en/referencia/manifesto/).
