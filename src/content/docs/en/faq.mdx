## About Rustploy

### What is Rustploy?

Rustploy is a single-node, self-hosted PaaS written in Rust. It deploys Docker containers with zero-downtime swaps, a reverse proxy with automatic HTTPS, an embedded registry, scheduled jobs and an MCP server. It runs as one binary, `rustployd`, on a VPS with Docker. See [What is Rustploy](/en/comece/o-que-e/).

### What is Rustploy not for?

Rustploy is not for more than one server, for hundreds of containers, or for builds without a Dockerfile. It manages **one** Linux machine with Docker, does not cluster, and building from source requires a `Dockerfile` (there are no buildpacks). For multiple hosts, see the [comparisons](/en/comparativos/visao-geral/).

### How much memory does Rustploy use?

The project targets under 50 MB of RAM at idle, but that number is a goal, not a published measurement. The daemon, proxy, SQLite database and registry run in a single process. What really weighs on the server is your applications and builds, so plan for at least 1 GB of RAM on the VPS.

### Is Rustploy free? What is the license?

Yes, Rustploy is free and open source, under the MIT license declared in the `Cargo.toml` of the three repositories (`rustploy-daemon`, `rustploy-gui` and `rustploy-shared`). The code is at github.com/antoniofernandodj/rustploy.

### Do I need to know Docker?

Yes, the documentation assumes you already know images, containers, networks, volumes, Dockerfiles and Docker Compose. Rustploy automates what you would do by hand with Docker. The [Docker to Rustploy](/en/comece/docker-para-rustploy/) table translates each concept.

### Which systems does Rustploy run on?

The daemon runs on Linux with systemd and Docker Engine, on x86_64 or aarch64. The desktop app has Linux and Windows builds. The desktop app does not support macOS, but the web UI works in any browser.

## Installation and access

### How do I install Rustploy?

With one command, on a Debian or Ubuntu VPS: `curl -fsSL https://raw.githubusercontent.com/antoniofernandodj/rustploy/main/install.sh | sudo sh`. It downloads the `rustployd` `.deb` from the latest GitHub release, checks the SHA-256, installs it, generates a token and prints the connection token. The package creates the `rustploy` user, the systemd service and the firewall helper. See [Quick install](/en/instalacao/instalacao-rapida/). If you prefer to build it, or have no access to GitHub, use the `.deb` built with `make deb-rustploy` ([Install the daemon on the VPS](/en/instalacao/instalar-daemon/)).

### Do I need git on the server?

Yes, if any service uses a Git source: cloning uses the server's `git` command, and the `.deb` package does not list it as a dependency. Install it with `sudo apt-get install git`. Without it the deploy fails with "falha ao iniciar git" (failed to start git). See [Deploy from a Git repository](/en/guias/git/).

### Where do I get the connection token?

The connection token comes from `sudo rustployd access-key` on the VPS, from `[api].connection_token` in `config.toml`, or from Settings → Web Server in the app. It is the base64 of `host:port::token` and only exists if `[api].token` is set. See [First access](/en/instalacao/primeiro-acesso/).

### How do I reach the dashboard from another machine?

Set `[api].bind_address = "0.0.0.0"` and a strong `[api].token` in `config.toml`, restart the daemon and open port 9797 in the firewall. The daemon refuses to start with a public bind and no token. For HTTPS, set `[api].domain`. See [Install the daemon on the VPS](/en/instalacao/instalar-daemon/).

### I edited config.toml and nothing changed. Why?

The file probably has an error and the daemon ignored it **silently**, falling back to the defaults. Invalid TOML, a missing required section or a wrongly typed value (`port = "9797"` with quotes) discards the whole file, with no log warning. Check with `sudo rustployd access-key`: if it says there is no token, the file was not read. See [The config.toml file](/en/instalacao/config-toml/).

### How do I update Rustploy?

Install the new `.deb` over the old one with `sudo dpkg -i`. Your data in `/var/lib/rustploy`, `config.toml` and `master.key` are preserved, and the service containers keep running. See [Update Rustploy](/en/instalacao/atualizar/).

## Deploys

### I created the service but nothing is running. Why?

Creating a service does not deploy it: it starts stopped and empty. Open the service, set the source (Git, image or zip), the port and the healthcheck, and click **Deploy**. See the [first deploy tutorial](/en/tutorial/primeiro-deploy/).

### Why did my deploy fail?

The cause is in the deploy's **build log**, on the `==> Erro em [State]: …` line. In the desktop app, open the service, the Deployments tab, and click **≡** on the deploy's row. The most common causes are a missing Dockerfile, no `git` on the server and a healthcheck that does not pass. See [The lifecycle of a deploy](/en/conceitos/ciclo-de-vida/).

### My deploy is stuck in Pending. What is that?

Rustploy runs **one deploy at a time** on the whole server, and the others wait in a queue. See the queue on the Deploy Engine screen. If the queue is **paused**, deploys wait until you resume it. A queued deploy can be promoted to the top or cancelled. See [The deploy queue](/en/guias/fila-de-deploys/).

### How do I roll back to the previous version?

Redeploy the previous version: put back the image, branch or commit that worked and click **Deploy**. The Rollback button does not redeploy: it only finds the previous deploy. If a deploy fails its healthcheck, Rustploy automatically keeps the old container. See the [tutorial](/en/tutorial/primeiro-deploy/).

### Is the deploy really zero-downtime?

Yes, as long as the healthcheck is configured. The new container starts next to the old one, passes the healthcheck, and only then does the proxy switch the route in one step. A new service starts with the healthcheck set to **None**, in which case Rustploy only checks that the container is up, not that the app responds. Configure an HTTP healthcheck. See [Healthcheck](/en/guias/healthcheck/).

### Can I deploy on every Git push?

Yes, with the **deploy webhook**: every Application service has a secret URL, and a `POST` to it triggers the deploy. It works with GitHub, GitLab, Gitea, Docker Hub and GitHub Actions, and pushes to other branches are ignored. The URL only appears after the first deploy. See [Deploy webhooks](/en/guias/webhooks/).

### My Dockerfile `ARG` arrives empty. Why?

Rustploy's `docker build` runs **without** the project or service variables: there are no *build args*. Variables only reach the running container. Read the value at runtime or, if the build needs it, use a Compose stack with `build.args`. See [How environment variables are resolved](/en/conceitos/variaveis-de-ambiente/).

### I changed an environment variable and nothing changed. Why?

Variables are handed to the container when it is **created**, so the change only applies on the next **Deploy**. Reload just restarts the existing container and does not apply new variables. The same goes for changing a secret's value. See [Environment variables and secrets](/en/guias/variaveis-e-secrets/).

### My monorepo cannot find the Dockerfile. What do I adjust?

Point **CONTEXT PATH** at the app folder (for example `apps/web`) and **DOCKERFILE** at the file inside it. The Dockerfile path is relative to the context, and Rustploy checks that it exists before calling Docker. The **WATCH PATHS**, **BUILD PATH** and **BUILD STAGE** fields appear on screen, but the deploy does not use them yet. See [Deploy from a Git repository](/en/guias/git/).

### Can I deploy without a Dockerfile?

Not to build from source: Rustploy has no buildpacks and requires a `Dockerfile`. Without a Dockerfile you can use a ready-made image from a registry, a Compose stack or a template from the catalog. See [Service and sources](/en/conceitos/servico-e-fontes/).

## Domains, networking and HTTPS

### My domain returns 502. How do I diagnose it?

A 502 means the proxy found the route but the container did not respond. Check the Ingress screen: if the domain is missing, no deploy registered the route; if the target port is wrong, fix the domain's port on the Domains tab. Also check that the app listens on `0.0.0.0` and that the healthcheck passes. See [Diagnose a 502 error](/en/guias/diagnosticar-502/).

### The HTTPS certificate is not issued. What do I check?

Check, in this order: the domain's DNS points at the server, `ingress.acme.enabled` is `true` with an `email`, ports 80 and 443 are open to the internet, and the service reached `Live` (the certificate is requested after the deploy). Let's Encrypt must reach port 80 through the domain name. See [Domains and automatic HTTPS](/en/guias/dominios-e-tls/).

### How does my application find the database?

Inside a project, services reach each other by name on the project network: an Application service answers as `rp_<name>`, and a Compose service by its service name **inside the YAML**. The database's Connection tab shows the internal URL ready to copy. See [Networking and names](/en/conceitos/rede-e-nomes/).

### How do I reach a database from outside the server?

Open a host TCP port: on the service's Domains tab use **PORTA TCP DO HOST** (Salvar porta or Automática), or tick the external URL option in the desktop wizard. Rustploy allocates a port from the 20000–20999 range and opens it in the firewall. This exposes the database to the internet, protected only by its password: use a strong one. See [Databases and brokers](/en/guias/bancos-e-brokers/).

### Can a service have several domains?

Yes, each service can have several domains, each with its own container port and with or without TLS. They live on the Domains tab. In a Compose stack only one container serves the domain: set the ingress target if the default pick is wrong. See [Domains and automatic HTTPS](/en/guias/dominios-e-tls/).

## Data, backups and security

### Does Rustploy back up my databases?

No, Rustploy does not back up the data in your databases or volumes. Use a scheduled job that runs `pg_dump`, `mysqldump` or `mongodump` to a host path and copy that path off the server. Also back up Rustploy's own state and the `master.key`. See [Backup and restore](/en/guias/backup/).

### Do my services come back by themselves after the server reboots?

Probably not. According to the code, containers are created with restart policy `no`, and on startup the daemon marks services without a running container as stopped. The plan to start everything at boot is not implemented yet. After a reboot, deploy your services. Verify on your server before relying on it. See [Monitoring, health and automatic restart](/en/operacao/monitoramento-e-saude/).

### Is there read-only access or per-user access control?

No, the API uses a single administrator token, with no scopes and no users. Whoever has the token can do anything, including reading decrypted secrets, and destructive commands do not ask for confirmation. Protect the token like the root password, use HTTPS and, if possible, a VPN. See [Server security](/en/operacao/seguranca-do-servidor/).

### The token leaked. What do I do?

Change `[api].token` in `config.toml`, restart the daemon and sign in again on the clients. The `connection_token` rewrites itself. If the token was in AI agents, remove and register the MCP again. See [Server security](/en/operacao/seguranca-do-servidor/).

### I lost master.key. Can I recover the secrets?

No: without the master key at `/etc/rustploy/master.key`, stored secrets cannot be decrypted, and a database backup alone does not help. Keep a copy of the key off the server. You will have to recreate the secrets. See [Environment variables and secrets](/en/guias/variaveis-e-secrets/).

### Where are my application's logs?

The runtime log is read from Docker **live** and is not stored: when a deploy swaps the container, the old one's log is gone. Open it on the service's Logs tab. Each deploy's **build log** is stored. For application log history, ship logs off the server. See [Log windows](/en/interface/logs/).

## AI agents and MCP

### How do I connect Claude Code to Rustploy?

In Settings → Web Server, use the **Conectar um agente (Claude Code)** button to copy the command `claude mcp add --transport http rustploy https://HOST:PORT/mcp --header "Authorization: Bearer <token>"` and run it in your terminal. Then open a **new** Claude Code session. See [Connect Claude Code to Rustploy](/en/agentes/conectar-claude-code/).

### What can an AI agent do on my server?

An agent can list services, trigger a deploy and wait for the result, read the build log, diagnose a 502 and run any protocol command through the `rpc` tool. There are nine MCP tools. The access is the same as an administrator's. See [Operate Rustploy with AI agents](/en/agentes/visao-geral/) and the [tools reference](/en/agentes/ferramentas/).

### Is it safe to give the token to an AI agent?

Only with caution: the token is an administrator's, the server does not ask for confirmation on destructive commands (`ServiceDelete`, `Prune*`, `Remove*`) and there is no read-only mode. Tell the agent to describe and wait for your confirmation before acting, name each server and use MCP only on trusted networks. See [Security when using agents](/en/agentes/seguranca/).

## Migration and operations

### Can I migrate from Dokploy?

Partly: the `rustploy-import` importer copies projects, Git applications, Compose stacks, variables and each service's first domain. It does not convert Docker image applications, databases, secrets or volumes, and the direct write can delete services with the same name. Run with `--dry-run` first. See [Migrate from Dokploy](/en/migracao/dokploy/).

### How do I copy a service to another server?

Use **Exportar serviço** on the service screen to generate a file and **Importar** in the New service wizard on the other server. The service is created without a deploy and nothing is overwritten. Only the configuration travels: data, volumes and secrets do not. To move the whole server, use the [Infrastructure as Code manifest](/en/guias/infra-as-code/).

### What is the difference between Deploy, Reload and Rebuild?

**Deploy** runs the full cycle (build or pull, new container, healthcheck, route swap). **Reload** only restarts the container that is running, without applying new variables or a new image. In the desktop app, **Rebuild** calls the same function as Deploy. See [The service screen](/en/interface/servico/).

### Should I use the desktop app or the web UI?

Either works for daily use: both talk to the same API. The web UI needs no installation and works on a phone as a PWA. The desktop app keeps several servers, has a system tray icon and notifies you when a deploy finishes, even with the window closed. Some features only exist through the API or MCP. See [Install the clients](/en/instalacao/instalar-clientes/).

### How is Rustploy different from Dokploy, Coolify or CapRover?

Rustploy manages a single machine with one binary and its own proxy, and has native MCP. The other three manage more than one server (or use Swarm), have larger communities and more features, such as backups and notifications. See the [comparison overview](/en/comparativos/visao-geral/).
