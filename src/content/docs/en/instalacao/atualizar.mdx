title: Update Rustploy
description: How to update the Rustploy daemon and clients without losing data - what is preserved on upgrade, how to reinstall the package and how the daemon resumes interrupted deploys.

## Finding out whether there is a new version

In **Settings → Atualizações** (in the app and in the web UI) the daemon asks GitHub for the latest stable
release and compares it with the running version. It is only a check: **nothing is installed**, and the
update itself follows the steps below. See [Settings](/en/interface/configuracoes/#atualizações-updates).

## Updating from Settings

If the server was installed from the `.deb`, the **Atualizar daemon** (update daemon) button (in **Settings → Atualizações**, in
the app and in the web UI) does everything: the daemon keeps a database snapshot, downloads the release's package and
signature, and asks a root helper to install it, which only installs what the project has **signed** (see
[the update helper](/en/operacao/seguranca-do-servidor/#the-update-helper)). The daemon restarts, but your services'
containers **keep running**.

- If a **deploy is running or queued**, the daemon refuses and asks whether you want to update anyway.
- If the service **does not become stable** after the install, the previous binaries come back by themselves.
- **Reverter para a versão anterior** (roll back) restores the binaries from the last update's backup. The database is **not**
  rolled back: if the new version migrated the schema, the snapshot kept before sits in `<db_path>/update_snapshots/` (the 3 most recent).
- In the desktop app the window returns to the login when the daemon restarts; sign in again and the tab shows the result. In
  the web UI the progress shows live.

The button only appears if the helper exists (a `.deb` install, with systemd). For other installs use the command below. The
**first** update to a version that has this feature has to be done with the command below, because the previous version
does not have the helper yet.

## Update the daemon

The shortest way is to run the [install command](/en/instalacao/instalacao-rapida/) again, which downloads the latest
release and installs it over the old one. It **keeps** `config.toml` (and the token) and changes nothing you already
configured:

```bash
curl -fsSL https://raw.githubusercontent.com/antoniofernandodj/rustploy/main/install.sh | sudo sh
```

In a terminal, the installer also **asks for the container engine** (Docker or Podman) and, if you switch to Podman,
migrates the volumes and redeploys: see
[Updating a VPS that runs on Docker](/en/instalacao/instalar-daemon/#updating-a-vps-that-runs-on-docker-switching-to-podman).
The same question appears in `make install-rustploy`, from the repository cloned on the VPS.

Or, by hand, install the new `.deb` over the old one:

```bash
sudo dpkg -i rustployd_<new-version>_*.deb
```

The package restarts the service by itself. What is preserved:

- **Your data**, in `/var/lib/rustploy` (the SQLite database, builds, the registry, variable backups).
- **The configuration**, `/etc/rustploy/config.toml`. It is marked as a package configuration file: `dpkg` asks before overwriting it if you edited it.
- **The master key** for secrets, at `/etc/rustploy/master.key`.

Your services' containers **keep running** during the daemon update: they belong to Docker, not to the
Rustploy process.

## What happens if a deploy was in progress

On startup the daemon looks for deploys in a non-terminal state and decides by the state they stopped in:
before the route swap the old container is still alive, so it is a safe *rollback*; a swap in progress is
inspected in Docker; `Promoting` is completed. The proxy's route table is rebuilt from Docker.

## Update the clients

- **Web UI**: it ships with the daemon. If the browser shows the old version, force a reload (`Ctrl+Shift+R`), because the files are served with a long cache.
- **Desktop app installed from the `.deb` (Linux)**: in **Settings → Atualizações**, the **App desktop** section shows the installed and latest versions; **Atualizar app** downloads the package, asks for the **administrator password** (the system's native dialog, through `pkexec`), installs it and reopens the app. The only program that gets root is `rustploy-gui-update`, which installs the project-**signed** `rustploy-gui` package and never a version that is not newer; it exists only during the authentication, and no root process stays resident on your computer. See [the app helper](/en/operacao/seguranca-do-servidor/#the-desktop-app-helper).
- **Desktop app any other way** (Windows, portable zip, `cargo install`): the tab shows the new version and the install command. Run the command again (Linux: `… | sudo sh -s -- gui`; Windows: `irm … | iex`) or replace the portable zip's folder.

:::tip
Back up `/etc/rustploy/master.key` and `/var/lib/rustploy` before big updates. Without the master key,
stored secrets cannot be decrypted.
:::
