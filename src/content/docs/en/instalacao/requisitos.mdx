## On the server

- **Linux** with **systemd**. The daemon runs as a service.
- A **container engine**: **Docker Engine** (default, socket at `/var/run/docker.sock`) or **Podman** 4.7+ (socket at `/run/podman/podman.sock`). The installer (`install.sh`) installs the chosen engine if it is missing (`--engine docker` or `--engine podman`); see [Choosing the container engine](/en/instalacao/instalar-daemon/#choosing-the-container-engine-docker-or-podman).
- **x86_64** or **aarch64** architecture.
- **1 vCPU and 1 GB of RAM** are enough for Rustploy itself; the rest is for your applications.
- **git**, if any service uses the Git source (cloning uses the server's `git`).
- (Optional) **ufw**, if you want Rustploy to open database and broker ports by itself.

## How much Rustploy uses

Measured on 2026-11-21, with the versions from release `v0.1.85`.

| Process | Own memory | RSS | Peak | Where |
|---|---|---|---|---|
| **Daemon** (`rustployd` 0.1.70) | **~17 MB** (`anon`) | ~36 MB | 49 MB (cgroup) | 1 vCPU production VPS, 8 services, GUI connected |
| **Desktop app** (`rustploy-gui` 0.1.78) | **~76 MB** (PSS), 31 MB anonymous | ~131 MB | 141 MB | Linux desktop, Intel HD 2500, open for 9 min |

- **Own memory** is what the process really takes. For the daemon it is the service's `anon`
  memory (without the file cache, which the kernel frees by itself). For the app it is the **PSS**,
  which splits shared libraries (GTK, the graphics driver) among the processes that use them. RSS
  counts those libraries in full, so it looks larger.
- **The daemon went from ~41 to ~17 MB** from 0.1.68 to 0.1.70, by using a single SQLite connection
  instead of up to ten.
- On the server, the total systemd shows (`systemctl status rustployd`) includes the file cache of the
  database and logs and grows over time; that cache does not weigh, because the kernel gives it back
  when memory runs short.
- The numbers vary with the number of services, connected clients and logs.

To measure on your server and your desktop:

```bash
# daemon: own memory (anon) and file cache (file), in bytes
grep -E '^(anon|file) ' /sys/fs/cgroup/system.slice/rustployd.service/memory.stat

# desktop app: RSS, PSS and anonymous memory, in kB
grep -E '^(Rss|Pss|Anonymous)' /proc/$(pgrep -x rustploy-gui)/smaps_rollup
```

## Compatible systems (glibc)

The daemon `.deb` requires **glibc 2.34 or newer** (`libc6 (>= 2.34)`) and the desktop app's, **2.35** (`libc6 (>= 2.35)`).
glibc already ships with every Debian and Ubuntu, so you install nothing: the system's version just has to be equal or
higher. If it is not,
the installer refuses **before downloading**, and `apt` would refuse the installation too.

| System | glibc | Supported |
|---|---|---|
| Debian 11 (bullseye) | 2.31 | **no** (neither) |
| Debian 12 (bookworm), current Raspberry Pi OS | 2.36 | yes |
| Debian 13 (trixie) | 2.41 | yes |
| Ubuntu 20.04 | 2.31 | **no** |
| Ubuntu 22.04 and Linux Mint 21 | 2.35 | yes |
| Ubuntu 24.04 | 2.39 | yes |
| Alpine and other musl distributions | do not use glibc | **no** |

To check yours: `getconf GNU_LIBC_VERSION`. The minimum version comes from where the binary is built (an Ubuntu 22.04):
built against a newer glibc, it would only run on systems equal or newer.

## Network

| Port | What for | Required |
|---|---|---|
| 80 | Ingress HTTP and the ACME challenge (certificate issuance) | for domains with TLS |
| 443 | Ingress HTTPS | for domains with TLS |
| 9797 | API, web UI, webhooks and MCP | yes, if clients are not on the VPS itself |
| 20000–20999 | Automatic external ports for databases and brokers | only if you expose TCP |

## Domains

Point a DNS `A` (or `AAAA`) record for each domain at the server's IP **before** you configure the
domain on the service. Let's Encrypt must reach the server's port 80 through that name to issue the
certificate.
