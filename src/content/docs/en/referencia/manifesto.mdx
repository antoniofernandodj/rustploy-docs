The **service bundle** (see [Copy a service between servers](/en/guias/copiar-servico/)) carries one
`service` as YAML. This page is the **field reference** for that `service`, generated from the
daemon and `rustploy-shared` code.

<Aside type="note" title="The whole-server manifest no longer exists">
  The old Infrastructure as Code manifest (`rustploy.yml` + `rustploy.vars.toml`, with `projects:`)
  was removed. For a copy of the whole infrastructure use [Download the infra](/en/guias/infra-as-code/);
  to restore, use [git sync](/en/guias/sincronizacao-git/).
</Aside>

## Fields

**Required** says whether the field must exist for the file to be accepted.

### `service`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `name` | text | yes | — | Required. **Matching key** within the project. |
| `source` | `source` object | yes | — | Required. Where the service comes from (see `source`). |
| `port` | integer | no | `0` | App port **inside** the container. If omitted, it is `0` (no error, but the service will have no useful port). |
| `host_port` | integer | no | absent | Legacy: **one** TCP port opened on the server, bound to the service `port`. `0` asks for automatic allocation (reuses the port already allocated to the service with the same name). With `tcp_ports`, it is only a mirror of the port that leads to `port`. |
| `tcp_ports` | list of TCP ports | no | empty | TCP ports opened on the server, **each one to a container port** (e.g. a storage's API and its console). At most 8. On import, each host port comes back as automatic. |
| `domain` | text | no | absent | **Legacy** domain (just one). Prefer `domains`. |
| `tls` | true/false | no | `false` | TLS for the legacy `domain`. |
| `domains` | list of domain routes | no | empty | Domain routes: each one with `domain`, `port` and `tls`. |
| `env` | map text → text | no | empty | Service variables. A `secret:NAME` value references a secret; `${KEY}` comes from the variables file. |
| `env_comments` | list of comments | no | empty | Comments from the `.env` editor, each anchored to a key. |
| `volumes` | list of texts | no | empty | Each item is `host:container` or `host:container:ro`. **An invalid item is silently dropped.** |
| `healthcheck` | `healthcheck` object | no | absent | Healthcheck. If omitted, the service has **no** healthcheck (`none`). |
| `replicas` | integer | no | `1` | Number of containers. Default and minimum `1` (`0` becomes `1`). |
| `resources` | `resources` object | no | absent | CPU and memory limits. |
| `command` | text | no | absent | Overrides the image command. |
| `args` | list of texts | no | empty | Command arguments. |
| `product` | text | no | absent | Managed product running in the service: database (`postgres`, `mongodb`, `mariadb`, `mysql`, `redis`), broker (`kafka`, `rabbitmq`, `nats`) or storage (`rustfs`, `minio`). Absent = ordinary service. Older bundles with the `db:` key are still accepted. |
| `shared` | true/false | no | `false` | Marks the service as a **shared database server**. The authorized projects live in the daemon, not in the manifest. |

### `source` (use **one** of the keys)

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `registry` | text | no | absent | Registry image (`nginx:latest`). |
| `git` | `git` object | no | absent | Git repository with a Dockerfile. |
| `compose` | text | no | absent | The YAML of a Compose stack, as text. |
| `compose_ingress` | text | no | absent | In Compose stacks, the service **inside the YAML** that receives the domain. Without it the daemon finds it by the domain port. |

### `source.git`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `url` | text | yes | — | Required. Repository URL. |
| `branch` | text | no | absent | Default `main`. |
| `root_path` | text | no | absent | Stored, but the deploy does **not use it** yet. Default `.`. |
| `dockerfile` | text | no | absent | Dockerfile path, relative to the context. Default `Dockerfile`. |
| `context` | text | no | absent | Folder sent as the build context. Default `.`. |
| `build_stage` | text | no | absent | Stored, but the deploy does **not use it** yet. |
| `submodules` | true/false | no | `false` | Stored, but the deploy does **not use it** yet. |
| `watch_paths` | list of texts | no | empty | Paths (relative to the repository root; `*` and `**` allowed) that a push must touch for the **webhook** to trigger a deploy. Empty: every push to the branch triggers. See [Webhooks](/en/guias/webhooks/#path-filter-watch_paths). |
| `username` | text | no | absent | Clone user, if the provider requires one. |
| `credentials` | text | no | absent | The **name** of a project secret holding the clone token. |
| `provider` | text | no | absent | The **name** of a connected Git account. If it does not exist at the destination (or in the variables file), the import **aborts**. |

### `healthcheck`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `type` | text | no | `tcp` | `none`, `tcp`, `http` or `docker` (uppercase works). **If omitted, it is `tcp`**, and any unknown value also becomes `tcp`. |
| `path` | text | no | absent | `http` only. Default `/`. |
| `status` | integer | no | absent | `http` only. Expected status, default `200`. |
| `interval` | integer | no | absent | Seconds between attempts. Default `5`. |
| `timeout` | integer | no | absent | Seconds per attempt. Default `3`. |
| `retries` | integer | no | absent | Attempts. Default `10`. |
| `start_period` | integer | no | absent | Seconds before the first attempt. Default `5`. |

### `resources`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `cpu_shares` | integer | no | `0` | CPU weight. `0` = no limit. |
| `mem` | text | no | absent | Memory limit: `1024`, `256k`, `256m` or `2g`. |

### Item of `domains`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `domain` | text | yes | — | Required. The domain name. |
| `port` | integer | no | absent | Container port for this domain. If omitted, the service `port` applies. |
| `tls` | true/false | no | `false` | Automatic HTTPS (ACME). |

### Item of `tcp_ports`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `host_port` | integer | yes | — | Required. The port on the server; `0` asks for automatic allocation. |
| `container_port` | integer | no | absent | Container port this port leads to. If omitted, the service `port` applies. |
| `label` | text | no | absent | Just a name for the screen ("console", "dashboard"); it does not change routing. |

### Item of `env_comments`

| Field | Type | Required | Default | |
|---|---|---|---|---|
| `text` | text | yes | — | The full line, including the `#`. |
| `before_key` | text | no | absent | The key that comes right after the comment. If omitted, it is a loose comment at the end. |


## Variable values: `secret:NAME`

An `env` value is plain text or `secret:NAME`, a reference to a **project secret** (the value is not in
the file). When exporting **without values**, plain values are redacted. See
[How variables are resolved](/en/conceitos/variaveis-de-ambiente/).

## Surprising behaviors

| You write | What happens |
|---|---|
| a field with a **typo** (`replica: 5`) | it is **silently ignored**: the parser does not reject unknown fields |
| two keys in `source` (`registry` and `git`) | the **first** wins in the order `registry`, `git`, `compose`; no error |
| `port` missing | it is `0`, no error |
| `healthcheck: { path: /saude }` without `type` | it is `tcp`; the `path` is ignored |
| a volume without `:` or with an empty side | it is **dropped** |
| `replicas: 0` | becomes `1` |
