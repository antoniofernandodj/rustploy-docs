No projeto aberto, clique em **+ Novo serviço**. O assistente abre numa janela
própria, **Novo serviço — nome do projeto**, com **‹ Voltar** e **Cancelar** no topo.
Criar um serviço **não faz deploy**: depois de criado, abra o serviço e clique em
**Deploy**.

## Escolha o tipo

<Shot
  src={tipos}
  alt="Janela Novo serviço com os seis tipos: Application, Database, Broker, Compose, Template e Importar."
  caption="Primeiro passo: o tipo de serviço."
/>

| Tipo | Descrição na tela | Quando usar |
|---|---|---|
| **Application** | Web app via Git ou imagem | seu código ou uma imagem pronta. Veja [Git](/guias/git/) e [zip](/guias/zip/) |
| **Database** | Banco de dados gerenciado | Postgres, MySQL, MariaDB, MongoDB ou Redis |
| **Broker** | Mensageria: Kafka, RabbitMQ, NATS | filas e eventos |
| **Compose** | Stack Docker Compose | vários containers juntos. Veja [Compose](/guias/compose/) |
| **Template** | A partir de um preset | aplicações prontas do [catálogo](/templates/) |
| **Importar** | Recriar um serviço exportado de outro servidor | levar um serviço de um Rustploy para outro |

Clique em **Selecionar ›** na linha do tipo.

## Database

<Shot
  src={banco}
  alt="Lista de bancos de dados: MongoDB, PostgreSQL, MariaDB, MySQL e Redis, cada um com a imagem padrão."
  caption="Escolha do banco, com a imagem padrão de cada um."
/>

| Banco | Imagem padrão |
|---|---|
| MongoDB | `mongo:8` |
| PostgreSQL | `postgres:18` |
| MariaDB | `mariadb:11` |
| MySQL | `mysql:8` |
| Redis | `redis:7` |

<Aside type="caution" title="mongo:8 em kernels novos">
  A imagem `mongo:8` não inicia em kernels Linux 6.19 ou mais novos. Nesses
  servidores, troque a imagem para `mongo:7` no formulário.
</Aside>

### O formulário

<Shot
  src={postgres}
  alt="Formulário Nova PostgreSQL com os campos Nome, Database name, User, Password gerada, a opção de URL externa e a imagem Docker."
  caption="Formulário do PostgreSQL."
/>

| Campo | O que é |
|---|---|
| **NOME** | o nome do **serviço** no Rustploy (ex.: `meu-banco`) |
| **DATABASE NAME** | o database criado dentro do servidor (padrão `app`) |
| **USER** | o usuário (padrão `postgres`) |
| **PASSWORD** | **gerada** para você, e você pode trocar |
| **Gerar URL de conexão externa** | marque para acessar o banco de **fora do servidor** (veja abaixo) |
| **DOCKER IMAGE** | a imagem, ex. `postgres:18` |

Clique em **Criar PostgreSQL**. Os campos mudam conforme o banco: MySQL e MariaDB
pedem também a senha do root, e o MongoDB tem **Use Replica Sets**.

<Aside type="caution" title="Anote a senha">
  A senha mostrada é a que vai valer. Copie-a antes de criar, ou consulte depois na
  aba **Environment** do serviço.
</Aside>

#### URL de conexão externa

Marcando **"Gerar URL de conexão externa (porta e firewall automáticos)"**, o
Rustploy aloca uma porta livre da faixa `[external_ports]` (padrão 20000–20999),
libera essa porta no `ufw` e mostra a **External URL** na aba **Connection** do
serviço. Isso deixa o banco acessível pela **internet**, protegido só pela senha.
Use uma senha forte. Sem marcar, o banco só é alcançável de dentro do projeto.
Detalhes em [Bancos e brokers](/guias/bancos-e-brokers/).

## Template

<Shot
  src={template}
  alt="Lista de templates com logo, nome e botão Escolher, e um campo de busca no topo."
  caption="Catálogo de templates, com busca."
/>

Use o campo **BUSCAR** (*"buscar templates…"*) para filtrar o catálogo pelo nome ou pela
descrição. Cada linha tem o logo, o nome e **Escolher ›**. Depois você dá um nome ao
serviço e revisa as variáveis (as senhas já vêm geradas). São mais de 380
aplicações: veja o [catálogo](/templates/).

## Application

<Shot
  src={wizApp}
  alt="Formulário Nova Application com os campos Nome e App name opcional, o aviso para configurar a origem na aba General e o botão Criar Application."
  caption="Nova Application: só o nome."
/>

O assistente pede só o **NOME** (e, opcionalmente, o **APP NAME**, usado no lugar do nome) e cria o
serviço **vazio**. A origem (**Git**, imagem ou zip), a porta e o domínio se configuram depois, na aba
**General** do serviço. Veja [Git](/guias/git/).

## Broker

<Shot
  src={wizBroker}
  alt="Lista de brokers com Apache Kafka, RabbitMQ e NATS, cada um com a imagem Docker e o botão Selecionar."
  caption="Escolha do broker."
/>

Três opções, cada uma com a imagem que vai rodar: **Apache Kafka** (`apache/kafka:3.9.0`), **RabbitMQ**
(`rabbitmq:4-management`) e **NATS** (`nats:2`). Depois de **Selecionar ›**, o formulário muda um pouco:

  caption="RabbitMQ pede **USER** e **PASSWORD** (a senha vem gerada; os valores estão borrados)."
/>

<Shot
  src={wizKafka}
  alt="Formulário Nova Apache Kafka com nome, password gerada, a opção de gerar URL de conexão externa, a imagem Docker e o botão Criar Apache Kafka."
  caption="Kafka: só **NOME** e **PASSWORD**."
/>

<Shot
  src={wizNats}
  alt="Formulário Nova NATS com nome, password gerada, a opção de gerar URL de conexão externa, a imagem Docker e o botão Criar NATS."
  caption="NATS: também só **NOME** e **PASSWORD**."
/>

| Campo | O que é |
|---|---|
| **NOME** | o nome do serviço |
| **USER** | só no RabbitMQ (padrão `rabbit`) |
| **PASSWORD (gerada, pode trocar)** | a senha. Já vem preenchida: troque se quiser |
| **Gerar URL de conexão externa** | abre uma porta TCP no servidor e no firewall, e mostra a URL de fora. Desligado, o broker só é alcançável pela rede do projeto |
| **DOCKER IMAGE** | a imagem, só para conferir |

Veja [Bancos e brokers](/guias/bancos-e-brokers/).

## Compose

<Shot
  src={wizCompose}
  alt="Formulário Nova Compose Stack com os campos Nome e App name opcional, o aviso para configurar o compose file dentro do serviço e o botão Criar Compose Stack."
  caption="Nova Compose Stack: só o nome."
/>

Como na Application, o app desktop pede só o **NOME** (e o **APP NAME** opcional) e cria a stack
**vazia**: *"Configure o compose file dentro do serviço antes de fazer deploy."* O YAML se edita na aba
**General** do serviço. Veja [Stacks Docker Compose](/guias/compose/).

## Importar

<Shot
  src={wizImport}
  alt="Passo Importar serviço exportado, com o botão Escolher arquivo, a caixa para colar o texto do pacote e o botão Analisar."
  caption="Importar um serviço exportado (o nome do projeto, no texto, está borrado)."
/>

Escolha o arquivo exportado de outro servidor (**Escolher arquivo…**) **ou cole o texto** do pacote, e clique
em **Analisar**. O serviço é criado **no projeto aberto**, **sem deploy** (*"revise e clique em Deploy
depois"*), e nada é sobrescrito. Só a configuração vem no arquivo: os **dados** (volumes, bancos) não. O passo
a passo, os avisos e as escolhas sobre variáveis estão em
[Copiar um serviço para outro servidor](/guias/copiar-servico/#importar).

## Depois de criar

1. Abra o serviço (**Abrir ›** no cartão).
2. Configure o [healthcheck](/guias/healthcheck/), o [domínio](/guias/dominios-e-tls/) e as variáveis.
3. Clique em **Deploy**.
