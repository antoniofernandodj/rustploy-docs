Dois conjuntos de dados precisam de backup: o **estado do próprio Rustploy** e os
**dados das suas aplicações**.

## 1. O estado do Rustploy

| O quê | Onde | Por quê |
|---|---|---|
| Pasta do daemon (`infra/` com o estado em YAML, e o SQLite do runtime) | `/var/lib/rustploy/db` | é o estado inteiro da plataforma |
| **Identidade `age`** | `/etc/rustploy/age.key` (ou `age_identity` no `config.toml`) | sem ela, os secrets gravados **não podem ser decifrados** |
| Configuração | `/etc/rustploy/config.toml` | token da API, domínios, ACME |
| Certificados TLS | `<db_path>/certs/` | evita reemitir (o Let's Encrypt limita) |
| Registry embutido | `<db_path>/registry/` | só se você o usa |

<Aside type="danger" title="A identidade age é insubstituível">
  Guarde o `age.key` **fora do servidor**, num cofre, e configure uma **chave de recuperação**. Um
  backup do banco sem a identidade deixa todos os secrets ilegíveis. Veja
  [Chaves e segredos](/guias/chaves-e-segredos/).
</Aside>

Faça a cópia com o daemon parado, ou use uma cópia consistente do SQLite. Os arquivos de `infra/` são YAML e podem ser versionados pela [sincronização com git](/guias/sincronizacao-git/).

### Um atalho mais barato: a infra

A [sincronização com o git](/guias/sincronizacao-git/) (ou o [zip da infra](/guias/infra-as-code/))
recria projetos e serviços em outro servidor. Ela **não** leva os dados dos volumes, e os secrets
vão cifrados. Complementa o backup do banco, não o substitui.

### Backup de variáveis

O snapshot automático das variáveis a cada 60 s foi **desligado** (a seção `[env_backup]` do
`config.toml` ainda é aceita, mas ignorada). O histórico das variáveis agora vem da
[sincronização com git](/guias/sincronizacao-git/); sem ela, use
[Baixar a infra](/guias/infra-as-code/).

## 2. Os dados das suas aplicações

O Rustploy **não faz backup dos dados dos bancos nem dos volumes**. Isso é com
você.

- **Bancos:** use um [job](/guias/jobs/) agendado que roda `pg_dump`, `mysqldump` ou `mongodump` e grava num caminho do host (bind mount), e então copie esse caminho para fora do servidor. O exemplo do guia de jobs é um backup de Postgres.
- **Volumes (bind mounts):** são pastas do host. Inclua-as no seu backup do servidor.
- **Snapshots do provedor** da VPS são uma camada extra útil.

## Testar a restauração

Um backup que nunca foi restaurado é uma hipótese. Restaure num servidor de teste
de vez em quando. Com a sincronização com git, o caminho é [restaurar num servidor novo](/guias/sincronizacao-git/#restaurar-num-servidor-novo).
