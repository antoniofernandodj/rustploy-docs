O `rustployd` lê a configuração de um arquivo TOML. No pacote `.deb` ele fica em
`/etc/rustploy/config.toml`, já completo.

## Onde ele é procurado

Na ordem, o **primeiro arquivo que existir e for válido**:

1. o caminho em `$RUSTPLOY_CONFIG`;
2. `/etc/rustploy/config.toml`;
3. `~/.config/rustploy/config.toml`.

Se nenhum servir, valem os padrões embutidos (veja a coluna *sem arquivo* abaixo).

<Aside type="danger" title="Um erro no arquivo não aparece em lugar nenhum">
  Se o arquivo não for um TOML válido, **ou** faltar uma seção obrigatória, **ou** um
  valor tiver o tipo errado (por exemplo `port = "9797"` com aspas), o daemon
  **ignora o arquivo inteiro em silêncio**, sem aviso no log, e segue para o próximo
  caminho ou para os padrões. Um erro de digitação pode, na prática, subir o daemon
  **sem o seu token e sem o seu domínio**. Depois de editar, confira que o daemon
  leu o que você escreveu (veja [Conferir](#conferir-o-que-o-daemon-leu)).
</Aside>

### Seções obrigatórias e opcionais

| Seção | Obrigatória? |
|---|---|
| `[daemon]`, `[ingress]` com `[ingress.acme]`, `[docker]`, `[deploy]`, `[metrics]`, `[secrets]` | **sim**, e todas as chaves delas (exceto `acme.email`) |
| `[api]`, `[env_backup]`, `[external_ports]`, `[registry]` | não: ausentes, usam o padrão. Dentro delas, **cada chave** é opcional |

Por isso `[registry]` com só `enabled = true` basta. Mas dentro de `[ingress]`,
omitir `https_port` invalida o arquivo todo.

## Padrões

Há **dois** conjuntos de padrões. O do **pacote** é o que você vê no
`/etc/rustploy/config.toml` recém-instalado. O **sem arquivo** é o do código,
quando nenhum arquivo é lido:

| Chave | Pacote `.deb` | Sem arquivo |
|---|---|---|
| `ingress.http_port` | **80** | **8080** |
| `ingress.https_port` | 443 | 443 |
| `ingress.acme.enabled` | **false** | **true** |
| `ingress.acme.email` | vazio | ausente |

Ou seja: sem arquivo, o ACME fica **ligado** (e sem e-mail), e o HTTP escuta em 8080.

## Chave por chave

### `[daemon]`

| Chave | Padrão | |
|---|---|---|
| `db_path` | `/var/lib/rustploy/db` | diretório do banco SQLite e dos dados (builds, certificados, registry) |
| `log_level` | `info` | o log é JSON estruturado |

Sob systemd, o unit define `RUSTPLOY_DB_PATH`, que **tem prioridade** sobre o
arquivo. Editar `db_path` no arquivo não muda nada nesse caso.

### `[api]` (opcional)

| Chave | Padrão | |
|---|---|---|
| `enabled` | `true` | desligar também desliga webhooks, web UI e MCP |
| `bind_address` | `127.0.0.1` | |
| `port` | `9797` | |
| `token` | nenhum | o token da API |
| `domain` | nenhum | com domínio, a API termina TLS **na própria porta** (ACME) |
| `max_connections` | `32` | |

<Aside type="caution">
  **Guarda de segurança:** o daemon se recusa a subir com `bind_address` que não
  seja loopback e sem `token`.
</Aside>

No `.deb`, o bloco `[api]` vem **comentado**: para usá-lo, descomente e preencha.

### `[ingress]` e `[ingress.acme]`

| Chave | | |
|---|---|---|
| `http_port` | obrigatória | porta do proxy HTTP (também recebe o desafio do Let's Encrypt) |
| `https_port` | obrigatória | |
| `bind_address` | obrigatória | |
| `acme.enabled` | obrigatória | ligar a emissão automática de certificados |
| `acme.email` | opcional | e-mail do Let's Encrypt |
| `acme.directory` | obrigatória | URL da CA (padrão `https://acme-v02.api.letsencrypt.org/directory`) |

O e-mail do ACME também se define em **Settings → Web Server**. O valor dessa tela
**tem precedência** sobre o arquivo e exige reiniciar o daemon.

### `[docker]`

| Chave | Padrão |
|---|---|
| `socket_path` | `/var/run/docker.sock` |

### `[deploy]`

| Chave | Padrão | |
|---|---|---|
| `drain_secs` | `10` | espera, depois da troca de rota, antes de remover o container antigo |
| `image_cache` | `2` | |

### `[metrics]`

| Chave | Padrão |
|---|---|
| `interval_secs` | `2` |
| `history_points` | `60` |

### `[secrets]`

| Chave | Padrão | |
|---|---|---|
| `master_key_path` | `/etc/rustploy/master.key` | a chave que cifra os secrets. **Faça backup.** |

### `[external_ports]` (opcional)

| Chave | Padrão | |
|---|---|---|
| `range_start` | `20000` | |
| `range_end` | `20999` | |

A faixa que o Rustploy usa para expor bancos e brokers. É também a **única** faixa
que o `rustployd-fw` aceita abrir no `ufw`.

### `[registry]` (opcional)

| Chave | Padrão | |
|---|---|---|
| `enabled` | `false` | |
| `port` | `5100` | o listener escuta **só em loopback** |
| `domain` | nenhum | expõe o registry publicamente (rota no ingress + certificado) |
| `storage_dir` | `<db_path>/registry/` | |

O domínio definido em **Settings → Web Server** tem precedência sobre o do arquivo.

### `[env_backup]` (opcional)

| Chave | Padrão | |
|---|---|---|
| `dir` | `<db_path>/env_backups/` | |
| `interval_secs` | `60` | |

### `[update]` (opcional)

| Chave | Padrão | |
|---|---|---|
| `enabled` | `true` | `false`: o daemon nem consulta o GitHub (VPS sem saída para a internet) |
| `repo` | `antoniofernandodj/rustploy` | `dono/nome` das releases consultadas. Fixo na config: a UI não escolhe de onde vem uma atualização |
| `cache_hours` | `6` | por quanto tempo vale o resultado (o GitHub limita a API anônima a 60 consultas por hora por IP) |
| `check_interval_hours` | `6` | de quantas em quantas horas o daemon consulta sozinho, para o selo de versão nova acender nas janelas abertas sem ninguém clicar em "Verificar". `0`: só quando pedem |
| `allow_agent_apply` | `false` | `true`: o agente MCP pode pedir `ApplyUpdate` e `UpdateRollback`. Veja [o helper de atualização](/operacao/seguranca-do-servidor/#o-helper-de-atualização) |

## Variáveis de ambiente

Elas **sobrescrevem** o arquivo (e os padrões):

| Variável | Sobrescreve |
|---|---|
| `RUSTPLOY_CONFIG` | o caminho do arquivo |
| `RUSTPLOY_DB_PATH` | `daemon.db_path` |
| `RUSTPLOY_LOG_LEVEL` | `daemon.log_level` (o `RUST_LOG` também é lido) |
| `RUSTPLOY_HTTP_PORT` | `ingress.http_port` |
| `RUSTPLOY_API_ENABLED` | `api.enabled` (`1`, `true`, `yes` ou `on` ligam; qualquer outro valor desliga) |
| `RUSTPLOY_API_BIND` | `api.bind_address` |
| `RUSTPLOY_API_PORT` | `api.port` |
| `RUSTPLOY_API_TOKEN` | `api.token` (vazio = sem token) |
| `RUSTPLOY_API_DOMAIN` | `api.domain` |
| `RUSTPLOY_REGISTRY_ENABLED` | `registry.enabled` |
| `RUSTPLOY_REGISTRY_PORT` | `registry.port` |
| `RUSTPLOY_REGISTRY_DOMAIN` | `registry.domain` |
| `RUSTPLOY_REGISTRY_STORAGE_DIR` | `registry.storage_dir` |

Com o `.deb`, o unit systemd lê também `/etc/rustploy/environment` (opcional).
É o lugar certo para variáveis como `RUSTPLOY_API_TOKEN` quando você não quer o
token no `config.toml`. Nesse caso o daemon **não grava** o `connection_token` no
arquivo: use `rustployd access-key`.

## Conferir o que o daemon leu

```bash
sudo systemctl restart rustployd
sudo rustployd access-key        # imprime o token de conexão
journalctl -u rustployd -n 30    # confira porta e domínio
```

Se o `access-key` responder "sem `[api].token` configurado" depois de você ter
definido um, o arquivo **não foi lido**: procure o erro de digitação, aspas
faltando ou uma seção obrigatória ausente.
