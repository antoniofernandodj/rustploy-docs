O caminho de instalação suportado é o pacote **`.deb`** do `rustployd`,
para Debian, Ubuntu e derivados. Ele cria o usuário `rustploy`, instala o
serviço systemd e sobe o daemon.

## Em um comando

Na VPS, como root:

```bash
curl -fsSL https://raw.githubusercontent.com/antoniofernandodj/rustploy/main/install.sh | sudo sh
```

O instalador baixa o `.deb` da **última release do GitHub**, confere o SHA-256, instala o motor de containers
(Docker, se faltar), instala, gera um token, sobe o
serviço e mostra o **token de conexão**. Para liberar o acesso de fora da VPS, acrescente `--remote` depois de
`sh -s --`. Todos os detalhes, as opções e como ler o script antes de rodar estão em
[Instalação rápida](/instalacao/instalacao-rapida/).

<Aside type="note" title="Prefere compilar, ou sem acesso ao GitHub?">
  Use um dos caminhos abaixo: `cargo install rustploy` (só o binário) ou o `.deb` gerado a partir do repositório
  (que cria o usuário, o serviço e o helper de firewall).
</Aside>

## Escolher o motor de containers: Docker ou Podman

O rustploy não roda os containers sozinho: ele usa um **motor de containers**, o programa que de fato cria e
executa cada serviço. Você escolhe com `--engine`, e **em qualquer dos dois o instalador instala o motor se ele
faltar**:

| | `--engine docker` (padrão) | `--engine podman` |
|---|---|---|
| Comando | `… \| sudo sh` | `… \| sudo sh -s -- --engine podman` |
| O que instala | Docker Engine (`docker-ce`), pelo repositório oficial da Docker | Podman (4.7 ou mais novo) e um provider de `compose` |
| RAM com a VPS parada | `dockerd` + `containerd` ficam sempre rodando (~100 a 150 MB) | **não há daemon**: o Podman só acorda quando o rustploy o chama |
| Sistemas | Debian 12+, Ubuntu 22.04+ | Debian 13+, Ubuntu 24.04+ (o `podman compose` só existe a partir da 4.7) |

<Tabs>
  <TabItem label="Docker (padrão)">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/antoniofernandodj/rustploy/main/install.sh | sudo sh
    # igual a: … | sudo sh -s -- --engine docker
    ```

    Se o `docker` já existe na máquina, o instalador **não mexe nele**. Se não existe, ele segue o
    [guia oficial da Docker](https://docs.docker.com/engine/install/ubuntu/): remove pacotes que conflitam
    (só os instalados: `docker.io`, `podman-docker`, `containerd`, `runc`…), adiciona o repositório apt da Docker
    (chave GPG + `/etc/apt/sources.list.d/docker.sources`), instala
    `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin` e liga o serviço `docker`.
    Em Debian usa o repositório `debian` da Docker; em derivados (Mint etc.) usa o codinome do Ubuntu/Debian base.
    Numa distribuição que ele não reconhece, cai no `docker.io` da própria distribuição.

    **À mão** (Ubuntu; em Debian troque `ubuntu` por `debian`):

    ```bash
    # 1. remover o que conflita (pule se nada disso estiver instalado)
    sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-compose-v2 \
      docker-doc docker-buildx podman-docker containerd runc | cut -f1)

    # 2. repositório apt da Docker
    sudo apt update
    sudo apt install ca-certificates curl
    sudo install -m 0755 -d /etc/apt/keyrings
    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
    sudo chmod a+r /etc/apt/keyrings/docker.asc
    sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
    Types: deb
    URIs: https://download.docker.com/linux/ubuntu
    Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
    Components: stable
    Architectures: $(dpkg --print-architecture)
    Signed-By: /etc/apt/keyrings/docker.asc
    EOF
    sudo apt update

    # 3. instalar e conferir
    sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
    sudo systemctl status docker
    ```

    Depois instale o rustploy normalmente (o `.deb` aceita o `docker-ce` como dependência).
  </TabItem>
  <TabItem label="Podman">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/antoniofernandodj/rustploy/main/install.sh | sudo sh -s -- --engine podman
    ```

    O instalador faz quatro coisas, nesta ordem:

    1. **Instala o Podman** e um provider de compose (`docker-compose-v2`, `docker-compose-plugin` ou
       `docker-compose`, o primeiro que existir). Isso vem *antes* do `.deb` do rustploy para que o `apt` não
       puxe o Docker junto (o pacote aceita `docker.io`, `docker-ce` **ou** `podman` como dependência).
    2. **Liga o `podman.socket`**: o systemd fica de guarda em `/run/podman/podman.sock` e acorda o Podman só
       quando o rustploy bate ali. É daí que vem a economia de RAM.
    3. **Dá ao usuário `rustploy` acesso a esse socket**, que nasce `root:root`. Um arquivo
       `/etc/systemd/system/podman.socket.d/rustploy.conf` com `SocketGroup=rustploy` faz isso valer para sempre
       (um `chgrp` à mão se perde quando o socket é recriado).
    4. **Aponta o rustploy para o Podman**: um arquivo `/etc/systemd/system/rustployd.service.d/podman.conf`
       troca a dependência de `docker.service` por `podman.socket`, e o `[docker] socket_path` do `config.toml`
       passa a ser `/run/podman/podman.sock`. (A seção continua se chamando `[docker]` por compatibilidade.)

    **À mão:**

    ```bash
    sudo apt install podman docker-compose-v2     # ou docker-compose-plugin / docker-compose
    sudo mkdir -p /etc/systemd/system/podman.socket.d /etc/systemd/system/rustployd.service.d
    printf '[Socket]\nSocketGroup=rustploy\nSocketMode=0660\n' | sudo tee /etc/systemd/system/podman.socket.d/rustploy.conf
    printf '[Unit]\nAfter=\nWants=\nAfter=network.target podman.socket\nWants=podman.socket\n[Service]\nEnvironment=RUSTPLOY_CONTAINER_ENGINE=podman\n' \
      | sudo tee /etc/systemd/system/rustployd.service.d/podman.conf
    sudo sed -i 's|^socket_path *=.*|socket_path = "/run/podman/podman.sock"|' /etc/rustploy/config.toml
    sudo systemctl daemon-reload
    sudo systemctl enable --now podman.socket
    sudo systemctl restart podman.socket rustployd
    ```
  </TabItem>
</Tabs>

<Aside type="caution" title="Trocar de motor não move o que já roda">
  Containers, imagens e volumes do Docker **não** são migrados para o Podman (e vice-versa): o motor novo começa
  vazio. Depois de trocar, faça o deploy de cada serviço de novo; bancos exigem atenção porque seus dados estão em
  volumes do motor antigo. Para liberar de fato a RAM do Docker, depois de migrar tudo:
  `sudo systemctl disable --now docker docker.socket`. O Podman é suportado só em modo **rootful** (a partir do
  socket em `/run/podman/`).
</Aside>

## O que o pacote instala

| Item | Onde |
|---|---|
| Daemon | `/usr/bin/rustployd` |
| Helper de firewall (root) | `/usr/libexec/rustployd-fw` |
| Configuração | `/etc/rustploy/config.toml` |
| Serviços systemd | `rustployd.service`, `rustployd-fw.socket`, `rustployd-fw.service` |
| Banco e dados | `/var/lib/rustploy` |

O pacote depende de `docker.io`, `docker-ce` **ou** `podman`. O serviço roda como o usuário
de sistema `rustploy`, que entra no grupo `docker`. Veja
[Escolher o motor de containers](#escolher-o-motor-de-containers-docker-ou-podman).

## Pelo crates.io

Se preferir compilar na própria máquina, o crate do daemon se chama
`rustploy` (o binário instalado é `rustployd`):

```bash
cargo install rustploy
```

Isso instala só os binários em `~/.cargo/bin`. Não cria o usuário, o serviço
systemd nem o `config.toml`: para um servidor de produção, prefira o `.deb`
abaixo.

## Gerar o pacote

Numa máquina com a toolchain Rust e o `cargo-deb`:

```bash
git clone --recurse-submodules https://github.com/antoniofernandodj/rustploy.git
cd rustploy
cargo install cargo-deb
make deb-rustploy
# gera rustploy-daemon/target/debian/rustployd_<versão>_<arq>.deb
```

Copie o `.deb` para o servidor e instale:

```bash
sudo dpkg -i rustployd_*.deb
sudo apt-get install -f     # só se faltar alguma dependência
```

## Conferir

```bash
systemctl status rustployd
journalctl -u rustployd -f
```

Por padrão a API escuta em `127.0.0.1:9797`, **sem token**. Isso serve para
testar na própria VPS, mas ainda não deixa nenhum cliente remoto entrar.

## Liberar o acesso remoto

<Aside type="tip" title="Já fez o comando de uma linha?">
  O instalador já gerou o token e gravou o `[api]` no `config.toml`. Com `--remote`, a API já escuta em
  `0.0.0.0:9797`: pule para o passo 4 (pegar o token) e o 5 (firewall). Sem `--remote`, rode o comando de novo
  com a opção.
</Aside>

<Steps>
1. Gere um token forte:

   ```bash
   openssl rand -hex 32
   ```

2. Edite `/etc/rustploy/config.toml` e abra a seção `[api]`:

   ```toml
   [api]
   bind_address = "0.0.0.0"
   port         = 9797
   token        = "<o token que você gerou>"
   ```

   O daemon se recusa a subir com `bind_address` público e sem `token`.

3. Reinicie:

   ```bash
   sudo systemctl restart rustployd
   ```

4. Pegue o [token de conexão](/instalacao/primeiro-acesso/):

   ```bash
   sudo rustployd access-key
   ```

5. Abra a porta 9797 no firewall do provedor e, se usar `ufw`, no `ufw`.
</Steps>

<Aside type="caution">
  Se o `config.toml` tiver um erro, o daemon o **ignora em silêncio** e sobe com os
  padrões. Se o passo 4 disser que não há token, o arquivo não foi lido. Veja
  [O arquivo config.toml](/instalacao/config-toml/#conferir-o-que-o-daemon-leu).
</Aside>

<Aside type="caution">
  Sem `[api].domain`, a porta 9797 fala **HTTP puro** e o token trafega sem
  cifra. Para uso real, configure um domínio (veja abaixo) ou feche a porta
  para a internet e acesse por VPN ou túnel SSH.
</Aside>

## Ligar o HTTPS

Aponte o DNS dos seus domínios para o servidor e ligue o ACME:

```toml
[ingress.acme]
enabled = true
email   = "voce@exemplo.com"
```

Para que o painel também use HTTPS, defina o domínio da API:

```toml
[api]
domain = "rustploy.meusite.com"
```

Reinicie o daemon. A referência completa está em
[O arquivo config.toml](/instalacao/config-toml/).
