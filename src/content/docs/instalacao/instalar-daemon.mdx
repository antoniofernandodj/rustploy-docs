O caminho de instalação suportado é o pacote **`.deb`** do `rustployd`,
para Debian, Ubuntu e derivados. Ele cria o usuário `rustploy`, instala o
serviço systemd e sobe o daemon.

## Em um comando

Na VPS, como root:

```bash
curl -fsSL https://raw.githubusercontent.com/antoniofernandodj/rustploy/main/install.sh | sudo sh
```

O instalador baixa o `.deb` da **última release do GitHub**, confere o SHA-256, instala, gera um token, sobe o
serviço e mostra o **token de conexão**. Para liberar o acesso de fora da VPS, acrescente `--remote` depois de
`sh -s --`. Todos os detalhes, as opções e como ler o script antes de rodar estão em
[Instalação rápida](/instalacao/instalacao-rapida/).

<Aside type="note" title="Prefere compilar, ou sem acesso ao GitHub?">
  Use um dos caminhos abaixo: `cargo install rustploy` (só o binário) ou o `.deb` gerado a partir do repositório
  (que cria o usuário, o serviço e o helper de firewall).
</Aside>

## O que o pacote instala

| Item | Onde |
|---|---|
| Daemon | `/usr/bin/rustployd` |
| Helper de firewall (root) | `/usr/libexec/rustployd-fw` |
| Configuração | `/etc/rustploy/config.toml` |
| Serviços systemd | `rustployd.service`, `rustployd-fw.socket`, `rustployd-fw.service` |
| Banco e dados | `/var/lib/rustploy` |

O pacote depende de `docker.io` ou `docker-ce`. O serviço roda como o usuário
de sistema `rustploy`, que entra no grupo `docker`.

## Pelo crates.io

Se preferir compilar na própria máquina, o crate do daemon se chama
`rustploy` (o binário instalado é `rustployd`):

```bash
cargo install rustploy
```

Isso instala só os binários em `~/.cargo/bin`. Não cria o usuário, o serviço
systemd nem o `config.toml`: para um servidor de produção, prefira o `.deb`
abaixo.

## Gerar o pacote

Numa máquina com a toolchain Rust e o `cargo-deb`:

```bash
git clone --recurse-submodules https://github.com/antoniofernandodj/rustploy.git
cd rustploy
cargo install cargo-deb
make deb-rustploy
# gera rustploy-daemon/target/debian/rustployd_<versão>_<arq>.deb
```

Copie o `.deb` para o servidor e instale:

```bash
sudo dpkg -i rustployd_*.deb
sudo apt-get install -f     # só se faltar alguma dependência
```

## Conferir

```bash
systemctl status rustployd
journalctl -u rustployd -f
```

Por padrão a API escuta em `127.0.0.1:9797`, **sem token**. Isso serve para
testar na própria VPS, mas ainda não deixa nenhum cliente remoto entrar.

## Liberar o acesso remoto

<Aside type="tip" title="Já fez o comando de uma linha?">
  O instalador já gerou o token e gravou o `[api]` no `config.toml`. Com `--remote`, a API já escuta em
  `0.0.0.0:9797`: pule para o passo 4 (pegar o token) e o 5 (firewall). Sem `--remote`, rode o comando de novo
  com a opção.
</Aside>

<Steps>
1. Gere um token forte:

   ```bash
   openssl rand -hex 32
   ```

2. Edite `/etc/rustploy/config.toml` e abra a seção `[api]`:

   ```toml
   [api]
   bind_address = "0.0.0.0"
   port         = 9797
   token        = "<o token que você gerou>"
   ```

   O daemon se recusa a subir com `bind_address` público e sem `token`.

3. Reinicie:

   ```bash
   sudo systemctl restart rustployd
   ```

4. Pegue o [token de conexão](/instalacao/primeiro-acesso/):

   ```bash
   sudo rustployd access-key
   ```

5. Abra a porta 9797 no firewall do provedor e, se usar `ufw`, no `ufw`.
</Steps>

<Aside type="caution">
  Se o `config.toml` tiver um erro, o daemon o **ignora em silêncio** e sobe com os
  padrões. Se o passo 4 disser que não há token, o arquivo não foi lido. Veja
  [O arquivo config.toml](/instalacao/config-toml/#conferir-o-que-o-daemon-leu).
</Aside>

<Aside type="caution">
  Sem `[api].domain`, a porta 9797 fala **HTTP puro** e o token trafega sem
  cifra. Para uso real, configure um domínio (veja abaixo) ou feche a porta
  para a internet e acesse por VPN ou túnel SSH.
</Aside>

## Ligar o HTTPS

Aponte o DNS dos seus domínios para o servidor e ligue o ACME:

```toml
[ingress.acme]
enabled = true
email   = "voce@exemplo.com"
```

Para que o painel também use HTTPS, defina o domínio da API:

```toml
[api]
domain = "rustploy.meusite.com"
```

Reinicie o daemon. A referência completa está em
[O arquivo config.toml](/instalacao/config-toml/).
