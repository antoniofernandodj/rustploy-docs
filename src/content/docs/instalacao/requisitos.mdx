## No servidor

- **Linux** com **systemd**. O daemon roda como serviço.
- Um **motor de containers**: **Docker Engine** (padrão, socket em `/var/run/docker.sock`) ou **Podman** 4.7+ (socket em `/run/podman/podman.sock`). O instalador (`install.sh`) instala o motor escolhido se ele faltar (`--engine docker` ou `--engine podman`); veja [Escolher o motor de containers](/instalacao/instalar-daemon/#escolher-o-motor-de-containers-docker-ou-podman).
- Arquitetura **x86_64** ou **aarch64**.
- **1 vCPU e 1 GB de RAM** bastam para o próprio Rustploy; o resto é para as suas aplicações.
- **git**, se algum serviço usar a fonte Git (o clone usa o `git` do servidor).
- (Opcional) **ufw**, se quiser que o Rustploy abra portas de banco e broker sozinho.

## Quanto o Rustploy consome

Medido em 21/11/2026, com as versões da release `v0.1.85`.

| Processo | Memória própria | RSS | Pico | Onde |
|---|---|---|---|---|
| **Daemon** (`rustployd` 0.1.70) | **~17 MB** (`anon`) | ~36 MB | 49 MB (cgroup) | VPS de 1 vCPU em produção, 8 serviços, GUI conectada |
| **App desktop** (`rustploy-gui` 0.1.78) | **~76 MB** (PSS), 31 MB anônima | ~131 MB | 141 MB | desktop Linux, Intel HD 2500, aberto há 9 min |

- **Memória própria** é o que o processo realmente ocupa. No daemon é a memória `anon` do serviço
  (sem o cache de arquivos, que o kernel libera sozinho). No app é o **PSS**, que divide as
  bibliotecas compartilhadas (GTK, o driver gráfico) entre os processos que as usam. O RSS conta
  essas bibliotecas inteiras e por isso parece maior.
- **O daemon caiu de ~41 para ~17 MB** do 0.1.68 para o 0.1.70, ao usar uma conexão só com o SQLite
  em vez de até dez.
- No servidor, o total que o systemd mostra (`systemctl status rustployd`) inclui o cache de
  arquivos do banco e dos logs e cresce com o tempo; esse cache não pesa, porque o kernel o devolve
  quando falta memória.
- Os números variam com a quantidade de serviços, de clientes conectados e de logs.

Para medir no seu servidor e no seu desktop:

```bash
# daemon: memória própria (anon) e cache de arquivos (file), em bytes
grep -E '^(anon|file) ' /sys/fs/cgroup/system.slice/rustployd.service/memory.stat

# app desktop: RSS, PSS e memória anônima, em kB
grep -E '^(Rss|Pss|Anonymous)' /proc/$(pgrep -x rustploy-gui)/smaps_rollup
```

## Sistemas compatíveis (glibc)

O `.deb` do daemon exige **glibc 2.34 ou mais nova** (`libc6 (>= 2.34)`) e o do app desktop, **2.35** (`libc6 (>= 2.35)`).
A glibc já vem em todo Debian e Ubuntu, então você não instala nada: só precisa que a versão do sistema seja igual ou
maior. Se não
for, o instalador recusa **antes de baixar**, e o `apt` também recusaria a instalação.

| Sistema | glibc | Suportado |
|---|---|---|
| Debian 11 (bullseye) | 2.31 | **não** (nenhum dos dois) |
| Debian 12 (bookworm), Raspberry Pi OS atual | 2.36 | sim |
| Debian 13 (trixie) | 2.41 | sim |
| Ubuntu 20.04 | 2.31 | **não** |
| Ubuntu 22.04 e Linux Mint 21 | 2.35 | sim |
| Ubuntu 24.04 | 2.39 | sim |
| Alpine e outras distribuições com musl | não usam glibc | **não** |

Para conferir a sua: `getconf GNU_LIBC_VERSION`. A versão mínima vem de onde o binário é compilado (um Ubuntu 22.04):
compilado numa glibc mais nova, ele só rodaria em sistemas iguais ou mais novos.

## Rede

| Porta | Para quê | Obrigatória |
|---|---|---|
| 80 | Ingress HTTP e desafio ACME (emissão do certificado) | para domínios com TLS |
| 443 | Ingress HTTPS | para domínios com TLS |
| 9797 | API, web UI, webhooks e MCP | sim, se os clientes não estão na própria VPS |
| 20000–20999 | Portas externas automáticas de bancos e brokers | só se você expõe TCP |

## Domínios

Aponte um registro DNS `A` (ou `AAAA`) de cada domínio para o IP do servidor
**antes** de configurar o domínio no serviço. O Let's Encrypt precisa
alcançar a porta 80 do servidor por esse nome para emitir o certificado.
